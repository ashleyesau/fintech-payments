What the project is

A realistic source of truth. The generator models merchant lifecycles, seasonal trading, card and instant EFT payments, and term loans collected through DebiCheck. Events depend on each other the way they do in a real book: a repayment needs a loan, a risk event points at a transaction. It is not real data, and parameters without a source document are marked illustrative in config/.

A pipeline that treats loss as the failure to avoid. Change capture confirms its position in the database only after the objects have landed. A crash replays the batch, and the replay is checked against what already exists rather than overwriting it.

Proof at each layer. Bronze is compared to the landed objects, and then replayed into a blank database and compared to the source, table by table.

A cost study of the warehouse

I ran a warehouse cost and performance study on this platform to see what the pipeline costs to run in BigQuery and Cloud Storage, and where that cost can be cut. The experiments were chosen to fit inside the free tiers, so the study cost nothing to run.

The recommendations went back into the project:

  • Incremental, partitioned intermediate models in dbt.
  • Literal date bounds on the two marts, so queries scan less.
  • A layered, test-gated build with retries and a full-refresh option.
  • Lag, slowly changing dimension and completeness tests, a BigQuery schema check, and dbt parse in CI.

Cloud Storage use is counted per command: the project used 47% of the month’s Class A operations across all of its verification runs.

Choices worth a closer look

  • Verification never skips quietly

    bronze.verify fails if the source database is unreachable. The one flag that skips the source comparison prints that the result is not full proof.

  • Least-privilege service accounts

    The CDC consumer can create and read landed objects but never update or delete one. The Bronze writer cannot write to the landing bucket.

  • Crash behaviour is tested, not assumed

    Fault injection at each commit step, a SIGKILL test, late and overlapping objects, and a lost catalog rebuilt from the bucket all reach the same digests as a clean run.

  • Costs are counted before they are spent

    Every command lists its Cloud Storage operations, and runs stop if actual use exceeds the estimate.

  • Documentation that fails the build

    A test fails if a command-line flag exists in the code but not in the README table, or the reverse.
